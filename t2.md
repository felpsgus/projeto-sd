# Trabalho 2: Exposição Web e API Gateway

## Descrição
Aproveitando o **tema de negócio escolhido pelo grupo no Trabalho 1**, vocês deverão evoluir a arquitetura adicionando um **API Gateway (REST/HTTP). O grupo deve ter, no máximo, 3 alunos.**

O API Gateway será responsável por receber requisições externas em formato JSON condizentes com o tema (ex: agendar consulta, criar usuário, enviar transação, registrar pedido, etc.), realizar validações de dados na entrada, autenticar a requisição e traduzir/orquestrar o chamado enviando a requisição empacotada em gRPC para os microsserviços internos.

> **Atenção**: O trabalho **deve estar rodando e funcional no dia da apresentação** para que o grupo receba a nota da aplicação prática.

 
## Requisitos do Trabalho
1. API Gateway (REST HTTP):
    - Exposição de pelo menos um endpoint REST público adequado ao tema do grupo (ex: POST /agendamentos, POST /transacoes, POST /recursos).

2. Validação na Borda:
    - Validação de payload JSON obrigatório para os campos essenciais do modelo de negócio do grupo.
    - Retorno do código de status **400 Bad Request** em caso de payload inválido e **201 Created** em caso de sucesso.

3. Segurança:
    - Middleware de verificação de autenticação 
    - Retorno do código **401 Unauthorized** caso o token seja ausente ou inválido.

4. Tradução e Delegação de Protocolo:
    - Tradução do payload JSON em requisição binária gRPC e repasse da chamada para o microsserviço de backend rodando no GCP.

## Entregas
1. **Código-fonte do projeto:** repositório GitHub contendo o API Gateway.

2. **Demonstração Prática:** execução e teste dos cenários de sucesso e falha (400, 401 e 201). Na apresentação, o mais importante é mostrar o código executando e funcionando a comunicação com a API.

 
## Apresentação
Data de apresentação: **22/10/2026**

Cada grupo terá **até 5 minutos** para apresentar e demonstrar o funcionamento prático da solução. **Apenas um aluno do grupo precisa apresentar**.

 
## Critérios de Avaliação
- Aplicação prática (60%):
  - O sistema deve estar rodando durante a apresentação.
  - Validação correta dos status HTTP (400, 401 e 201/200) e integração bem-sucedida REST → gRPC.

- Código (30%):
  - Organização do API Gateway, middlewares de segurança/validação e legibilidade do código.

- Apresentação oral (10%):
  - Clareza, objetividade e domínio do tema.
  - Cumprimento do tempo limite de 5 minutos: ultrapassar o tempo resultará em nota zero neste quesito.
