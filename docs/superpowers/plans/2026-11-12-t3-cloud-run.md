# T3 — Migração para Cloud Run: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** deixar o repositório pronto para o usuário subir o TodoList no Cloud Run + Cloud SQL por scripts e
runbook, com retry gRPC e o roteiro de queda do Tasks.

**Architecture:** o código de negócio não muda. Entram: (1) uma política de retry nativa do `Grpc.Net.Client`
nos clientes gRPC do Gateway e do Tasks; (2) o nginx do frontend aceitando upstream HTTPS; (3) as imagens
.NET em chiseled e uma imagem de migração; (4) scripts PowerShell + runbook em `deploy/cloudrun/`. O usuário
executa tudo no GCP.

**Tech Stack:** .NET 10 / Grpc.Net.ClientFactory 2.83.0 / xUnit + FluentAssertions; nginx-unprivileged;
PowerShell 7 + gcloud; Cloud Run, Cloud SQL (PG 18), Secret Manager, Artifact Registry.

**Spec:** [docs/superpowers/specs/2026-11-12-t3-cloud-run-design.md](../specs/2026-11-12-t3-cloud-run-design.md),
que também precisa ser lido. Nele, D-T3-1 a D-T3-6 e "Respostas à revisão do builder" são normativos.

- `dotnet build` sem warnings, `dotnet test`, `dotnet format --verify-no-changes`; no front, `npm test` e

- Nenhum segredo versionado. Os scripts leem segredos de arquivo local (`.secrets/jwt/`) ou de prompt
  `Read-Host -AsSecureString`, nunca de parâmetro em texto ou de arquivo do repo.
- **Nenhum script deste plano é executado contra o GCP pelo agente.** A verificação é `-DryRun` e
  leitura do texto impresso.
- Região `us-central1`, projeto `sd-26-2`, registry `us-central1-docker.pkg.dev/sd-26-2/todolist`,
  instância `banco-1`, VPC/sub-rede `default`.
- Nomes dos serviços Cloud Run: `todolist-frontend`, `todolist-gateway`, `todolist-identity`,
  `todolist-tasks`; Job: `todolist-migrate`.
- Retry só para `StatusCode.Unavailable`, `MaxAttempts` padrão 3, e **só** nestes RPCs:
  `identity.v1.IdentityService/ValidateUser`, `.../GetProfile`, `tasks.v1.TasksService/ListTasks`,
  `.../GetTask`. Os demais **não** têm retry (D-T3-2: na dúvida, sem retry). Confirme o `package` real dos
  `.proto` em `contracts/*/v1/*.proto` antes de escrever os nomes.
- Novas decisões: **D-44** (retry gRPC) e **D-45** (exposição interna + uma branch por entrega), em
  [tarefas/backend/DECISOES-PENDENTES.md](../../../tarefas/backend/DECISOES-PENDENTES.md). Novas tasks:
  **BE-43** (retry), **BE-44** (imagens/nginx para Cloud Run), **BE-45** (deploy Cloud Run + runbook),
  em `tarefas/backend/`, no formato das existentes (ver BE-42), com os CA de cada tarefa abaixo.

## Review Focus

1. **Retry duplicando escrita**: `CreateTask`/`Register`/`UpdateTask` com `Unavailable` precisam ser chamados
   **uma vez** só. O teste está na Task 2.
2. **Retry esgotado**: `ListTasks` sempre `Unavailable` deve parar em 3 chamadas e devolver `503` com
   `Retry-After`, sem travar até o deadline. O teste está na Task 2.
3. **F5 em rota profunda e `/api` com upstream HTTPS**: a armadilha do envsubst (`$uri`) e do Host errado.
   A verificação manual está na Task 4.
4. **Compose de dev quebrar**: depois das Tasks 4 e 5, `docker compose --profile full up -d --build` precisa
   subir, e o smoke tem que passar contra `http://localhost`. A verificação está na Task 5.
5. **Script de deploy com a ordem errada de URLs**: o gateway precisa das URLs de identity/tasks já
   criadas, e o frontend precisa da do gateway. O `-DryRun` imprime a ordem, e a revisão confere na Task 6.
